# Συγχρονισμός ημερολογίων Sunset Villas

## Τι χρειαζόμαστε από τον ιδιοκτήτη

Για κάθε πραγματικό σπίτι, ξεχωριστά:

1. Όνομα σπιτιού και αντιστοίχιση των αγγελιών Airbnb / Booking.
2. Ιδιωτικό **iCal export URL της Airbnb**. Η δημόσια διεύθυνση της αγγελίας δεν αρκεί.
3. Ιδιωτικό **iCal export URL της Booking** από το extranet.
4. Πληροφορία αν οι δύο πλατφόρμες είναι ήδη συνδεδεμένες μεταξύ τους ή υπάρχει channel manager.

Δεν χρειάζονται κωδικοί πρόσβασης. Τα ιδιωτικά URLs μπαίνουν μόνο στη φόρμα διαχείρισης του backend, όχι σε GitHub issues, source files ή δημόσια μηνύματα.

Για συνεχή λειτουργία χρειάζεται δημόσιο HTTPS backend και βάση δεδομένων. Ο κώδικας είναι έτοιμος για Cloudflare Workers + D1, αλλά στις 4 Νοεμβρίου 2026 δεν υπάρχει συνδεδεμένος λογαριασμός φιλοξενίας ή πραγματικό iCal feed. Δεν έχει ελεγχθεί ζωντανή σύνδεση με Airbnb / Booking.

## Οι έξι κατευθύνσεις

| Πηγή → Προορισμός | Πού γίνεται η ρύθμιση                                                 |
| ----------------- | --------------------------------------------------------------------- |
| Airbnb → Site     | Dashboard → Συνδέσεις → Airbnb → Σύνδεση iCal                         |
| Booking → Site    | Dashboard → Συνδέσεις → Booking → Σύνδεση iCal                        |
| Site → Airbnb     | Αντιγραφή iCal του site → εισαγωγή εξωτερικού ημερολογίου στην Airbnb |
| Site → Booking    | Ο ίδιος σύνδεσμος του site → εισαγωγή ημερολογίου στη Booking         |
| Airbnb → Booking  | Το export URL της Airbnb → εισαγωγή στη Booking                       |
| Booking → Airbnb  | Το export URL της Booking → εισαγωγή στην Airbnb                      |

Η μία φορά ρύθμιση των εισαγωγών στις πλατφόρμες γίνεται από τον ιδιοκτήτη μέσα στους λογαριασμούς του. Η αποθήκευση των δύο URLs στο site δεν αλλάζει μόνη της τις ρυθμίσεις των πλατφορμών. Δεν αντικαθιστούμε υπάρχουσες συνδέσεις ή channel manager χωρίς προηγούμενο έλεγχο της τρέχουσας διάταξης.

Το site εξάγει **μόνο δικές του επιβεβαιωμένες κρατήσεις, ενεργές προσωρινές δεσμεύσεις και χειροκίνητα κλεισίματα**. Δεν επανεξάγει τις εισαγόμενες κρατήσεις. Έτσι δεν ανακυκλώνει επ’ αόριστον μια εισαγόμενη δέσμευση όταν αυτή ακυρωθεί στην πηγή. Αναγνωρίσιμα δικά του UIDs που επιστρέφουν από εξωτερικό feed αγνοούνται. Οι πλατφόρμες μπορεί να αλλάζουν UIDs ή τον τρόπο εξαγωγής κλειστών ημερομηνιών· η πραγματική διάταξη χρειάζεται έλεγχο ανά κατάλυμα πριν χρησιμοποιηθεί για κρατήσεις.

## Τι δείχνει το dashboard

- Μηνιαίο ημερολόγιο όλων των πηγών, χωρίς περιορισμό στα 200 πιο πρόσφατα αιτήματα.
- Ξεχωριστό χρώμα για site, Airbnb, Booking και χειροκίνητες δεσμεύσεις.
- Τελευταία επιτυχής εισαγωγή, τελευταία προσπάθεια, προγραμματισμένος επόμενος έλεγχος, αριθμός δεσμεύσεων και σφάλμα ανά feed.
- Χειροκίνητο κλείσιμο ημερομηνιών και άνοιγμα της συγκεκριμένης δέσμευσης. Η σημείωση του ιδιοκτήτη δεν εξάγεται.
- Κουμπί συγχρονισμού και ιδιωτικό export URL με κατάληξη `.ics`. Οι προηγούμενοι σύνδεσμοι χωρίς κατάληξη εξακολουθούν να λειτουργούν.

## Συμπεριφορά backend

Ο Worker cron εκτελείται ανά 15 λεπτά. Επιλέγει μέχρι έξι due feeds ανά εκτέλεση, ώστε οι SQL εντολές να χωρούν στο query budget της δωρεάν βαθμίδας D1. Με περισσότερα feeds χρειάζεται ανάλογη ρύθμιση συχνότητας/χωρητικότητας και έλεγχος ορίων· δεν υπόσχεται ότι απεριόριστα feeds ανανεώνονται όλα ανά 15 λεπτά.

Οι ανανεώσεις χρησιμοποιούν lease ανά feed, HTTP timeout, μέγιστο αρχείο 1 MB, έως 2.000 συμβάντα, ελεγχόμενα HTTPS hosts χωρίς redirects και conditional requests με ETag / Last-Modified. Το JSON bulk insert και η αντικατάσταση snapshot γίνονται ατομικά. Αλλαγή URL ακυρώνει εγγραφές παλιότερου in-flight συγχρονισμού.

Σε αποτυχία παραμένει το τελευταίο έγκυρο snapshot και ο επόμενος έλεγχος μετατίθεται με backoff. Η δημόσια διαθεσιμότητα αποτυγχάνει ελεγχόμενα όταν υπάρχει σφάλμα ή πολύ παλιά/ανύπαρκτη ενημέρωση, αντί να παρουσιάζει άγνωστες ημερομηνίες ως διαθέσιμες. Ο ιδιοκτήτης μπορεί να ζητήσει άμεση επανάληψη.

Υποστηρίζονται ολοήμερα μη επαναλαμβανόμενα VEVENTs. Ακύρωση ή διάφανο συμβάν δεν δεσμεύει νύχτες. Μη υποστηριζόμενες ημερομηνίες, επαναλήψεις, ελλιπές ή κακοσχηματισμένο αρχείο απορρίπτονται συνολικά. Δεν αποθηκεύονται ονόματα, περιγραφές, email ή τηλέφωνα από τις εξωτερικές κρατήσεις. Η αναχώρηση είναι αποκλειστική ημερομηνία: διαμονή 1–4 του μήνα δεσμεύει τις νύχτες 1, 2 και 3.

Το iCal ενημερώνει διαθεσιμότητα περιοδικά, δεν συγχρονίζει τιμές και δεν εγγυάται αποφυγή ταυτόχρονων κρατήσεων σε διαφορετικές πλατφόρμες. Η [Airbnb αναφέρει ανανέωση ανά 3 ώρες](https://www.airbnb.com/help/article/99). Η δυνατότητα και ο ρυθμός εισαγωγής της Booking χρειάζονται έλεγχο στο συγκεκριμένο extranet. Για άμεση διαχείριση αποθέματος απαιτείται κατάλληλος channel manager.

## Πριν από ζωντανή χρήση

Μετά τη φιλοξενία, την εισαγωγή των πραγματικών feeds και τη ρύθμιση των έξι κατευθύνσεων, ελέγχεται ελεγχόμενη δέσμευση και αφαίρεσή της σε κάθε προορισμό, με τον ιδιοκτήτη. Οι δοκιμές με fixtures δεν πιστοποιούν τη συμπεριφορά των πραγματικών λογαριασμών. Καταγράφουμε την ώρα τελευταίας ενημέρωσης που εμφανίζει κάθε πλατφόρμα και ελέγχουμε ότι μια ακύρωση απελευθερώνει τις αντίστοιχες ημερομηνίες μετά τον κύκλο ανανέωσης.

## Τοπική ανάπτυξη

Σε νέα κενή τοπική βάση εφαρμόστε με τη σειρά **όλα** τα `drizzle/*.sql`, αφού χτίσετε το backend. Αν η `0000` έχει ήδη εφαρμοστεί σε προηγούμενη τοπική έκδοση, εφαρμόστε μόνο τη νέα `0001_cooing_kinsey_walden.sql`. Μην επαναλαμβάνετε ήδη εφαρμοσμένα SQL αρχεία.

```sh
npm run typecheck
npm test
npm run build
npm run dev -- --port 5174
TEST_ADMIN_TOKEN='το-τοπικό-admin-token' node tests/integration.mjs
```

Τα tests χρησιμοποιούν SQLite/D1 και συνθετικά feeds. Δεν στέλνουν αιτήματα σε πραγματικά Airbnb / Booking iCal URLs και δεν περιλαμβάνουν πραγματικά credentials.
