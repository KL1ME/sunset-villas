# Συγχρονισμός ημερολογίων Sunset Villas

## Πλήρες app και προεπισκόπηση

Ο συγχρονισμός εκτελείται στο δημόσιο HTTPS backend Cloudflare Workers + D1. Το GitHub Pages προβάλλει μόνο το design και δεν εκτελεί API, cron, αιτήματα ή πληρωμές. Τοπική εισαγωγή ημερολογίου δεν ισοδυναμεί με παραγωγική σύνδεση.

Στη διαχείριση οι κωδικοί Κ1 και Κ2 αντιστοιχούν σε διαφορετικά πραγματικά σπίτια. Δεν είναι κωδικοί αγγελίας της Airbnb. Το Κ2 μπορεί να διαχειρίζεται ιδιωτικά ημερολόγια ενώ παραμένει προσχέδιο στο δημόσιο site.

## Στοιχεία που δίνει ο ιδιοκτήτης

Για κάθε κατάλυμα χρειάζονται η αντιστοίχιση των δύο αγγελιών, το ιδιωτικό iCal export URL της Airbnb και το αντίστοιχο URL της Booking από το extranet. Η δημόσια διεύθυνση μιας αγγελίας δεν είναι ημερολόγιο. Καταγράφεται επίσης αν υπάρχει ήδη σύνδεση ανάμεσα στις πλατφόρμες ή channel manager.

Τα ιδιωτικά URLs καταχωρίζονται μόνο στη φόρμα Συνδέσεων του backend. Δεν μπαίνουν σε source files, GitHub issues, δημόσιες αναφορές ή screenshots. Δεν χρειάζονται κωδικοί πρόσβασης στις πλατφόρμες.

## Ρύθμιση των κατευθύνσεων

| Πηγή → Προορισμός | Ρύθμιση                                                                                            |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| Airbnb → Site     | Διαχείριση → Συνδέσεις → κατάλυμα → Airbnb → Σύνδεση iCal                                          |
| Booking → Site    | Διαχείριση → Συνδέσεις → κατάλυμα → Booking → Σύνδεση iCal                                         |
| Site → Airbnb     | Αντιγραφή iCal του site για το συγκεκριμένο κατάλυμα → εισαγωγή εξωτερικού ημερολογίου στην Airbnb |
| Site → Booking    | Ο ίδιος σύνδεσμος του συγκεκριμένου καταλύματος → εισαγωγή ημερολογίου στη Booking                 |
| Airbnb → Booking  | Διατήρηση υπάρχουσας εισαγωγής του Airbnb export στη Booking                                       |
| Booking → Airbnb  | Διατήρηση υπάρχουσας εισαγωγής του Booking export στην Airbnb                                      |

Η προσθήκη των πηγών στο site δεν μεταβάλλει τις ρυθμίσεις των εξωτερικών λογαριασμών. Ο ιδιοκτήτης προσθέτει τον **τελικό δημόσιο σύνδεσμο iCal του site** στην Airbnb και στη Booking, ξεχωριστά για κάθε πραγματικό σπίτι. Δεν αντιγράφει το iCal του Κ1 στο Κ2 ή το αντίστροφο. Οι ήδη υπάρχουσες συνδέσεις Airbnb–Booking παραμένουν ως έχουν· δεν διαγράφονται και δεν δημιουργούνται διπλές εισαγωγές χωρίς έλεγχο.

Το export του site περιλαμβάνει μόνο τις δικές του επιβεβαιωμένες κρατήσεις, ενεργές προσωρινές δεσμεύσεις και χειροκίνητα κλεισίματα. Δεν περιλαμβάνει στοιχεία επισκεπτών ή εσωτερικές σημειώσεις και δεν επανεξάγει συμβάντα που εισήχθησαν από πλατφόρμα. Αναγνωρίσιμα δικά του UIDs που επιστρέφουν από εξωτερικό feed αγνοούνται. Η πραγματική συμπεριφορά των πλατφορμών, ιδίως στις ακυρώσεις, ελέγχεται στην εγκατάσταση του ιδιοκτήτη.

## Παύση πηγής και εξαίρεση Booking Κ1

Κάθε σύνδεση έχει χωριστή ενεργοποίηση. Η **Παύση σύνδεσης** ζητά επιβεβαίωση από τον διαχειριστή και εμφανίζει σαφή προειδοποίηση για χειροκίνητο έλεγχο. Το τελευταίο snapshot διατηρείται στη βάση, αλλά τα συμβάντα της πηγής σε παύση εξαιρούνται από την αυτόματη διαθεσιμότητα και το ενοποιημένο ημερολόγιο. Η παύση δεν σημαίνει επιτυχή συγχρονισμό και δεν αλλάζει τίποτα στους λογαριασμούς Airbnb ή Booking.

Το Booking Κ1 παραμένει η γνωστή εξαίρεση, σε παύση μέχρι ο ιδιοκτήτης να επιλύσει το σφάλμα του export με την Booking. Η εμφάνιση «Invalid Token» δηλώνει ότι η ίδια η Booking απορρίπτει το token. Από αυτό το μήνυμα δεν προκύπτει ότι η αιτία είναι η ηλικία της καταχώρησης ή λάθος αντιγραφή.

Με έγκυρο export URL γίνεται αλλαγή της σύνδεσης και ενεργοποίηση με νέο έλεγχο. Πριν από κάθε επιβεβαίωση κράτησης ο ιδιοκτήτης ελέγχει και τις πηγές που βρίσκονται σε παύση. Αποτυχία ή παλιά ενημέρωση **ενεργής** πηγής διατηρεί τη συμπεριφορά ασφαλούς αποτυχίας της διαθεσιμότητας.

## Διαχείριση & αιτήματα

Η είσοδος στο `/admin` δημιουργεί υπογεγραμμένη συνεδρία οκτώ ωρών σε `HttpOnly`, `SameSite=Strict` cookie, με `Secure` σε HTTPS. Το API διατηρεί υποστήριξη bearer `ADMIN_TOKEN` για scripts. Οι ιδιωτικοί εξωτερικοί σύνδεσμοι δεν επιστρέφονται στον client ως πεδία του dashboard.

Η διαχείριση περιλαμβάνει:

- Μηνιαίο ημερολόγιο όλων των ενεργών πηγών, με χρώματα ανά site, Airbnb, Booking και χειροκίνητο κλείσιμο.
- Κατάσταση ανά feed: τελευταία προσπάθεια/επιτυχία, επόμενος έλεγχος, πλήθος συμβάντων, σφάλμα ή παύση.
- Χειροκίνητο κλείσιμο νυχτών και άνοιγμα της συγκεκριμένης δέσμευσης, χωρίς διαγραφή κρατήσεων άλλων πηγών.
- Κουμπί άμεσου συγχρονισμού και ιδιωτικό export URL `.ics`. Η προηγούμενη μορφή χωρίς κατάληξη εξακολουθεί να λειτουργεί.
- Αναζήτηση/φίλτρα/σελιδοποίηση αιτημάτων, ορισμό συμφωνημένου ποσού, ιδιωτικές σημειώσεις και επιβεβαίωση/ακύρωση χωρίς πληρωμή.
- Ένδειξη τελευταίου κύκλου συγχρονισμού και τελευταίας συντήρησης ως heartbeat.

Τα αιτήματα δεν δεσμεύουν νύχτες. Η επιβεβαίωση απαιτεί συμφωνημένη τιμή και έλεγχο Airbnb / Booking από τον ιδιοκτήτη. Ο server επανελέγχει τις ενεργές πηγές και πραγματοποιεί την αλλαγή κατάστασης και τη δέσμευση νυχτών σε ατομική συναλλαγή. Η αναχώρηση είναι αποκλειστική: διαμονή 1–4 του μήνα δεσμεύει τις νύχτες 1, 2 και 3.

Ο επισκέπτης βλέπει την εξέλιξη από ιδιωτικό σύνδεσμο με token στο URL fragment. Η απάντηση δεν εμφανίζει στοιχεία επικοινωνίας, σημειώσεις ή κλειδιά πρόσβασης. Μπορεί να αποσύρει μόνο εκκρεμές αίτημα. Ο ιδιοκτήτης έχει χειροκίνητα στοιχεία επικοινωνίας και αντιγραφή του συνδέσμου· **δεν έχει συνδεθεί υπηρεσία αυτόματης αποστολής email**.

## Αυτόματη λειτουργία backend

Ο παραγωγικός Worker cron `*/15 * * * *` λειτουργεί χωρίς ανοιχτό browser. Επιλέγει έως έξι ενεργά due feeds ανά κύκλο, σε σειρά επόμενου ελέγχου. Με περισσότερα feeds απαιτείται έλεγχος συχνότητας και χωρητικότητας· δεν υπόσχεται ότι απεριόριστα καταλύματα ανανεώνονται όλα ανά 15 λεπτά. Ο έλεγχος διαθεσιμότητας μπορεί επίσης να ζητήσει ανανέωση παλιών πηγών.

Οι ανανεώσεις χρησιμοποιούν lease, HTTP timeout, όριο 1 MB/2.000 συμβάντων και conditional requests με ETag / Last-Modified. Γίνονται δεκτά μόνο επίσημα HTTPS hosts της αντίστοιχης πλατφόρμας, συμπεριλαμβανομένων των Airbnb `.gr` URLs. Τα redirects δεν ακολουθούνται. Το bulk insert και η αντικατάσταση snapshot είναι ατομικά· αλλαγή URL ή παύση ακυρώνει προηγούμενο in-flight συγχρονισμό.

Σε αποτυχία διατηρείται το τελευταίο έγκυρο snapshot και εφαρμόζεται backoff. Ενεργό feed με σφάλμα, ανύπαρκτη ή υπερβολικά παλιά ενημέρωση δεν επιτρέπει να παρουσιαστεί άγνωστη διαθεσιμότητα ως διαθέσιμη. Ο ιδιοκτήτης μπορεί να ζητήσει άμεση επανάληψη. Δεν αποθηκεύονται ονόματα, περιγραφές, email ή τηλέφωνα από τις εξωτερικές κρατήσεις· τα μηνύματα σφάλματος δεν περιέχουν raw upstream responses ή ιδιωτικά tokens.

Υποστηρίζονται ολοήμερα, μη επαναλαμβανόμενα VEVENTs. Ακυρωμένα ή διάφανα συμβάντα δεν δεσμεύουν νύχτες. Μη υποστηριζόμενες ημερομηνίες, επαναλήψεις, διπλά UIDs ή κακοσχηματισμένα αρχεία απορρίπτονται συνολικά.

Η συντήρηση ενημερώνει ληγμένα αιτήματα/προσωρινές δεσμεύσεις και ολοκληρωμένες διαμονές. Μετά τον ρυθμισμένο χρόνο από την αναχώρηση ανωνυμοποιεί στοιχεία επικοινωνίας, εσωτερικές σημειώσεις και access tokens μόνο σε terminal εγγραφές (`completed`, `cancelled`, `expired`). Οι ενεργές/μελλοντικές κρατήσεις και οι εγγραφές που παραμένουν προς έλεγχο διατηρούνται. Η τελευταία ολοκλήρωση καταγράφεται ανεξάρτητα από το heartbeat των ημερολογίων.

## Δοκιμαστική λειτουργία & πληρωμές

Οι αρχικές ρυθμίσεις χρησιμοποιούν ενδεικτική επιχείρηση/επικοινωνία και εμφανίζουν **DEMO**. Ο ιδιοκτήτης συμπληρώνει πραγματικά στοιχεία υπευθύνου, επικοινωνία, επαφή απορρήτου, χρόνο διατήρησης και πολιτική ακυρώσεων πριν απενεργοποιήσει το `demo_mode`. Η εφαρμογή δεν δέχεται τη μετάβαση σε κανονική λειτουργία με εμφανώς ενδεικτικά στοιχεία ή ελλιπείς υποχρεωτικές ρυθμίσεις.

Οι πληρωμές παραμένουν απενεργοποιημένες, ακόμη και αν υπάρχουν παλιά Stripe test keys. Το production config θέτει `PAYMENTS_ENABLED=disabled`. Η τιμή `test` είναι ρητή επιλογή μελλοντικών δοκιμών προγραμματιστή, με test key και webhook secret· δεν ενεργοποιεί live πληρωμές.

## Έλεγχος πριν από πραγματικές κρατήσεις

1. Αντικατάσταση ενδεικτικών στοιχείων επιχείρησης/επικοινωνίας και οριστικοποίηση τιμών και όρων από τον ιδιοκτήτη.
2. Επιτυχές δημόσιο deployment, ενεργό cron και πρόσφατα heartbeats/καταστάσεις ενεργών feeds.
3. Εισαγωγή του τελικού site iCal στην Airbnb και στη Booking για κάθε κατάλυμα, με διατήρηση της υπάρχουσας μεταξύ τους σύνδεσης.
4. Ελεγχόμενη δοκιμή δέσμευσης και άρσης της σε κάθε προορισμό, με τον ιδιοκτήτη. Καταγραφή της ώρας ανανέωσης που εμφανίζει κάθε πλατφόρμα.
5. Επιβεβαίωση ότι μια ακύρωση απελευθερώνει τις αντίστοιχες ημερομηνίες μετά τον κύκλο ανανέωσης και ότι η γνωστή πηγή σε παύση ελέγχεται χειροκίνητα.

Οι δοκιμές με fixtures και η επιτυχής ανάγνωση εξωτερικών feeds δεν πιστοποιούν από μόνες τους την τελική εισαγωγή του site στις πλατφόρμες. Το iCal δεν μεταφέρει τιμές ή όρους και δεν εγγυάται αποφυγή ταυτόχρονων κρατήσεων σε διαφορετικά κανάλια. Η [Airbnb αναφέρει ανανέωση ανά τρεις ώρες](https://www.airbnb.com/help/article/99). Δεν έχει συνδεθεί channel manager ή άμεσο API αποθέματος.

## Τοπική ανάπτυξη

Σε νέα κενή τοπική βάση εφαρμόστε με τη σειρά όλα τα `drizzle/*.sql`, αφού χτίσετε το backend. Σε υπάρχουσα εγκατάσταση εφαρμόστε μόνο όσα migrations λείπουν: η `0001` προσθέτει τη διαχείριση ημερολογίων, η `0002` τους εσωτερικούς κωδικούς και η `0003` τα guest access/idempotency πεδία, τις ρυθμίσεις και την ενεργοποίηση feed. Μην επαναλαμβάνετε ήδη εφαρμοσμένα SQL αρχεία.

```sh
npm run typecheck
npm test
npm run build
npm run dev -- --hostname 127.0.0.1 --port 5174
TEST_ADMIN_TOKEN='το-τοπικό-admin-token' node tests/integration.mjs
```

Τα tests χρησιμοποιούν SQLite/D1 και συνθετικά feeds/στοιχεία. Δεν καλούν πραγματικά ημερολόγια, δεν στέλνουν email και δεν εκτελούν πραγματικές πληρωμές. Εκτελούνται μόνο σε αναλώσιμη loopback βάση.

## Ιδιωτική τοπική εγκατάσταση

Το απομονωμένο προφίλ πραγματικών ημερολογίων χρησιμοποιεί διαφορετική βάση από τα tests και δεν αναπτύσσεται στην παραγωγή.

```sh
npm run build
npm run prepare:calendars
npx wrangler d1 migrations apply DB --local --config dist/server/wrangler.calendar-preview.json --persist-to .wrangler/private-calendars
npm run preview:calendars
```

Η διαχείριση ανοίγει στο `http://127.0.0.1:5195/admin`. Το `prepare:calendars` δημιουργεί ξεχωριστό τυχαίο `ADMIN_TOKEN` στο αγνοημένο `.dev.vars.calendar-preview`, με δικαιώματα αρχείου `0600`. Ο διαχειριστής χρησιμοποιεί το κλειδί στη φόρμα σύνδεσης· δεν το αντιγράφει σε δημόσια μηνύματα ή αρχεία. Τα feeds καταχωρίζονται μόνο στην ιδιωτική φόρμα και αποθηκεύονται στην τοπική βάση `.wrangler/private-calendars`.

Τα migrations αυτού του προφίλ παρακολουθούνται από το Wrangler· η ίδια εντολή εφαρμόζει μόνο τα εκκρεμή. Μετά από νέο build επαναλάβετε το `prepare:calendars`. Μην τρέχετε integration fixtures εδώ.

Ο server ακούει μόνο στο loopback, δεν λειτουργεί συνεχώς και δεν ενεργοποιεί αυτόματα το παραγωγικό cron. Τα τοπικά export URLs δεν εισάγονται στις πλατφόρμες. Μετά το deployment τα πραγματικά feeds καταχωρίζονται ιδιωτικά στη βάση παραγωγής· η τοπική βάση δεν δημοσιεύεται και δεν ανεβαίνει στο GitHub. Τα βήματα παραγωγικής ανάπτυξης βρίσκονται στο [README](../README.md#ανάπτυξη-σε-cloudflare).
